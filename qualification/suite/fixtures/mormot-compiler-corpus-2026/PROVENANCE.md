# mORMot compiler corpus

The source is prepared from the public HTTPS repository at exact commit
`bc189414f1b9ea163d24029cc8e814405e8e0cb5`.

`static/x86_64-linux` contains only the six Linux x86-64 inputs from the
matching `mormot2static.tgz` archive. The archive SHA-256 was
`ae2d8da212c5b4f2778370de7aee965f7fd82eef911da27eeb797d6db06db449`;
their checksums are recorded in `static/x86_64-linux.SHA256SUMS`.

This snapshot is compiler-test input. It is not the MoonBot product mORMot and
must not replace `qualification/vendor/mormot-product`.

The runner copies this exact checkout into a disposable work tree, then applies
the versioned Unicode source patch and `mormot-compiler-corpus-2026-test-contract.diff`.
The latter makes the JSON decimal serializer test pass an explicit `Double`:
the untyped decimal-to-Variant carrier is Currency under Delphi and Double under
FPC, so that spelling is not a serializer oracle. The public checkout stays
clean; both patch hashes are recorded in result provenance.

`People.json.gz` is a timestamp-free gzip of the 1,028,877-byte, 8,227-row
`data/People.json` generated by a full regression pass at the pinned corpus
commit.  Its compressed SHA-256 is
`64d2799dd98dd41264e673dd69adeeecda246df1b709fcdd184226df4e3a1b4a`;
the decompressed SHA-256 is
`583a7bc4e54a584e9221d76cdbaadd6287e127845908b9eb9fa3ff85e5170123`.
The fixed file ensures exact and candidate compilers consume identical JSON
instead of independently generated, variable ORM data.

`sample.json` is the fixed three-field Unicode object consumed by the corpus's
optional sample paths.  Its SHA-256 is
`3541d8423015fbbc1a0bf1b3c9e9df02027dc164eabb9b0dda385515dd5d02fa`.
